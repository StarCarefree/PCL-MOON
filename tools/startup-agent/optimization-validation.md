# 启动 Agent 优化验证（2026-11-06）

## 改动

- Java 21 单 JAR 累计 4 次缺失后才建表，成功查询不触发枚举。登记与预算操作留在全局锁内，枚举移到锁外；同一 JAR 并发构建时其他查询回退原查找。
- 单 JAR 索引保留条目哈希，供整条类路径聚合复用，不再次枚举 JAR。哈希数组共享 2 MiB 预算；超出预算或遇到不支持形态时保守回退。原有路径变更、关闭、超时失效保护保留。
- Java 17 不再初始化 `NegativeCache` 或开放 JDK 加载器内部包；启动器只对标记为 Forge 的 Java 17 实例自动注入。手动挂载 Agent 时仍由类文件哈希限定真正的补丁目标。
- Java 17 Forge 层关闭时不提取 bootstrap helper；metrics 关闭时不创建、更新 Forge 读取计数器。
- 启动器复用已计算的资源 SHA-256；游戏计时脚本改为增量扫描新增完整日志行。

Agent 仍默认关闭，不缓存转换后的字节码，不调整 Mod 加载顺序，不跳过 Mixin、签名或类定义。

## Java 21 合成查询对照

使用 `benchmark.py`，32 个 JAR，每个 1,000 个 `.class` 资源，每场景 4,000 次查询。资源查询不读取内容、不调用 `loadClass`，URLClassLoader 无父加载器。无 Agent、旧版、新版交错运行；每组 6 次、每次独立 JVM；metrics 关闭。

查询循环总耗时中位数（含首次查询）：

| 场景 | 无 Agent | 旧版 Agent | 新版 Agent | 新版相对旧版 |
| --- | ---: | ---: | ---: | ---: |
| 第一 JAR 内全部命中 | 38.94 ms | 42.32 ms | 41.01 ms | -3.1% |
| 整条类路径大量不同缺失 | 60.00 ms | 93.14 ms | 75.39 ms | -19.1% |
| 命中与缺失交错 | 64.13 ms | 101.44 ms | 90.94 ms | -10.3% |

大量缺失场景的首次查询中位数从 43.17 ms 降到 22.45 ms，进程创建至退出中位数从 300.05 ms 降到 279.71 ms。

**新版相对旧版减少了开销，但该短负载下无 Agent 仍更快。** 这是合成查询结果，不是 Minecraft 启动时间；没有预热 JIT 或清空系统文件缓存，各 Agent 在第一轮后复用其 helper。不能由此承诺任意整合包提速。

原始结果：`artifacts/test/startup-agent-opt/lookup-benchmark/results.json`。
